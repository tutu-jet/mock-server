从一条测试通知开始

  1. 安装 Google 版 App，开启手机系统通知权限。
  2. 选择指定设备并填写 FCM Token，或选择全局发送并填写已订阅的 Topic；再选择类型，填写标题、正文和目标 ID。
  3. 点击“发送通知”，检查 FCM 是否接受消息。
  4. 在手机通知栏点击消息，验证详情页面。发送历史可载入修改后再次发送。

本页通过 FCM 发送真实推送，发送到指定设备或 Topic 订阅设备。它不会向后端通知列表写入记录。

指定设备与全局发送

指定设备使用该设备的 FCM Token。全局发送使用 Topic，默认 all_users，只覆盖当前 Firebase 项目中成功订阅该 Topic 的设备，没有发送给全部 Token 的通配符。

客户端需要先调用 FirebaseMessaging.getInstance().subscribeToTopic("all_users") 并确认订阅成功；也可以由受信任服务端通过 Firebase Admin SDK 将已知设备 Token 订阅到该 Topic。填写 Topic 名称时不要加 /topics/ 前缀。未订阅的旧客户端不会收到。

表单与 JSON 可以相互切换；message 只能包含 token 或 topic 之一。发送历史会保留原发送范围，重新发送 Topic 消息仍发给该 Topic 当前的订阅设备。

获取设备 FCM Token

Android Studio 运行 Google Debug 版 App，Logcat 搜索：

 tag:FCM_TOKEN level:DEBUG

复制日志中的完整 Token。Fetching device FCM token 只是开始获取；等后面的字符串，不要复制时间、标签或引号。重装 App 或清除数据后，Token 可能变化。

Token 按 Firebase 项目自动保存在当前浏览器，刷新页面或重启服务后会自动填入。换设备直接修改，清空输入框可删除保存；清除浏览器网站数据后需要重新填写。请始终使用同一个地址（例如 localhost:9088），不同浏览器或地址的保存互不共享。

测试详情页 noauth

  1. 手机连接本机代理，确认 HTTPS 请求能出现在“流量”页。
  2. 选择 Incident 或 CAC Event，填写目标 ID。
  3. 打开整体 Mock：案例把 Case → Detail → CaseListItem-Detail 切到“无权限”；事件让 MobileEventDetailHeader 返回 403。
  4. 发送通知并点击，查看详情页的无权限状态。

使用匹配该详情请求的 403 Mock 时可填测试 ID；使用真实接口时，必须提供该账号无权访问且接口确认返回 403 的真实 ID。不存在的 ID 可能只返回 404 或空数据。

FCM 已接受，手机却没有通知？

先检查系统通知权限、当前设备 Token，以及 Google Play 服务的推送连接。在电脑终端执行：

adb shell dumpsys activity service com.google.android.gms/.gcm.GcmService | grep -E 'Not connected|Is client connected|Reconnect Scheduler Alarm'

Is client connected: true 表示已连接；false 表示未连接。能打开 Google 网页或取得 Token，不代表推送连接已建立。

VPN 要覆盖 Google Play 服务。连接连续失败后可能进入较长重试等待；切换网络后可开关飞行模式，再确认 VPN 已连接，重新检查。代理排查时先关闭手机 Wi-Fi 代理，收到后再恢复代理测试 403。

App 在前台时通常显示在通知栏，不一定弹出横幅；在后台时由系统展示。不要强行停止 App 后测试接收。

服务器发送凭据

凭据相当于服务器“发通知的钥匙”，设备 Token 是“接收手机的地址”，两者不同。在项目根目录的 .env 中配置一次：

GOOGLE_APPLICATION_CREDENTIALS=./credentials/fcm-service-account.json
FCM_PROJECT_ID={{ project }}

相对路径从项目目录解析。以后直接运行 main.py，或在终端执行：

uv run main.py

IDE 的 Python 解释器选择项目 .venv/bin/python；首次使用先执行 uv sync。启动时自动读取 .env，不需要手动 export。

也支持 FCM_ACCESS_TOKEN 或 Google 默认凭据。身份需要 cloudmessaging.messages.create 权限。401 常见于令牌过期，403 常见于权限或项目不匹配，404 可能是失效设备 Token。

.env 和凭据文件不提交到 Git，不写入历史或通知 JSON。页面需在运行服务器的电脑上通过 localhost 打开。
