# 多设备流量页设计

## 目标与当前行为

现有 mitmproxy 代理可接收多个客户端连接，但 FlowRecord 不包含客户端来源，全部请求进入同一个 1000 条环形缓冲。第一版补齐来源识别、设备筛选和按设备清空，优先覆盖 2–5 台设备同时调试。5 台是设计验证目标，不是已经测得的容量上限，也不做硬性接入限制。

## 页面布局

保留顶部导航与实时接收状态。在流量列表上方增加设备栏：全部设备、每台设备的名称与 IP，以及设备管理入口。设备较多时横向滚动，窄屏允许横向滑动。选中设备保持明显的边框与选中状态，不能只靠颜色识别。

设备栏下显示当前范围的流量条数与 Mock 命中数，并保留“忽略 Host”和清空操作。明确显示“Mock 规则对全部设备生效”。

列表增加来源设备列：时间、设备、方法、状态、请求地址、耗时、规则 / 操作。只查看单台设备时隐藏设备列，给请求地址更多空间。窄屏将设备名放入每条记录的第二行。

详情抽屉增加设备名、客户端 IP、客户端端口和发生时的平台信息。客户端端口仅用于排查，不参与设备分组。

## 设备识别与管理

- 在代理客户端连接事件中读取来源地址，不能使用 UI 浏览器的 IP 或请求自行携带的转发头作为设备身份。
- 第一版按当前服务会话内的客户端 IP 分组，同一设备多个 TCP 连接仍属于一个分组。IPv4 / IPv6 地址需要规范化。
- 新来源自动出现，默认名为“设备 · IP”；允许修改别名和手动选择 Android / iOS / 其他 / 未知。
- User-Agent 只能作为平台识别提示；无法判断时显示“未知”，不猜测机型。
- 不把 IP 当作跨网络永久身份。IP 改变时产生新分组，服务重启后重新发现设备。持久化设备绑定和合并历史不属于第一版。
- 显示“正在通信”“最近活跃”“暂无连接”及最后活跃时间。状态仅代表代理观察到的连接 / 请求，不能声称手机在线或离线。普通 HTTP 长连接空闲与 TLS 失败均需正确处理。
- 没有完成 HTTP 请求时也应能发现已建立代理连接的来源。TLS 错误可给出检查证书信任的提示，帮助区分“设备没接入”和“接入后 HTTPS 失败”。

## 筛选与实时更新

- 默认“全部设备”，也可单选一台；第一版不增加复杂的多选组合。
- 设备选择属于当前浏览器查看偏好，不能修改其他查看者的设备筛选或代理行为。
- 历史列表与 SSE 新流量必须使用同一范围；切换设备时更新列表、计数及订阅，避免旧设备请求插入新视图。
- 首次快照、订阅建立与切换之间使用事件序号和去重 / 补齐机制，避免丢失或重复请求。重连后重新同步保留的历史；已淘汰的数据明确提示，不承诺无限补发。
- 所选设备暂无新请求时保留历史与选择。空列表提示“此设备暂无流量”，提供切换全部设备和查看接入帮助的入口。
- 设备栏发现和状态事件单独更新；即使当前流量被 Host 过滤，设备仍能被发现。忽略 Host 继续沿用现有全局设置，并明确其作用范围。
- 流量统计基于当前范围内保留且未被 Host 过滤的记录，使用“当前保留”措辞，不显示为无限累计总量。

## 清空与规则作用范围

- 全部设备视图的按钮为“清空全部流量”；单设备视图为“清空此设备流量”。确认提示明确设备名与范围。
- 清空同时删除对应内存记录及原始 body，广播带范围与事件序号的 clear 事件，所有打开的页面同步更新。已排队的旧事件不得重新插回已清空记录。
- 清空不删除设备名称、不关闭连接、不停用规则，不改变规则页累计命中次数。
- 第一版 Mock 规则与整体 Mock 开关继续对全部设备生效，筛选设备只改变查看范围。
- 如果后续需要 Android 返回 403、iOS 同时返回 200，需要增加按设备匹配及独立规则状态；不能仅在流量页放一个开关就宣称隔离。

## 数据与容量

FlowRecord 增加会话设备 ID、来源 IP / 端口、平台与设备名快照；设备注册表保存别名、平台、连接集合、最后活跃时间。每个会话设备 ID 对应规范化来源 IP，记录自身包含来源信息，设备名更新时列表可用注册表当前别名展示。

为避免高流量设备挤掉其他设备的记录，建议每设备最多保留 1000 条，总计最多 5000 条，并在页面说明保留范围。达到每设备上限时淘汰该设备最旧记录；达到总上限时淘汰全局最旧记录，同步删除 body。会话记录、设备注册表与 SSE 事件队列均应有明确容量和淘汰策略。大响应原始 body 还需考虑磁盘预算；条数上限不代表字节容量上限。

## 验收

1. Android 与 iOS 同时请求相同接口，全部视图准确显示来源；单设备视图不会混入另一台的请求。
2. 同一 IP 的多个连接只产生一台设备；客户端端口变化不新增设备，未知平台不被错误标注。
3. 新设备、空闲、断连、重新连接以及证书失败的来源状态准确，不把 SSE 浏览器连接当手机设备。
4. 切换筛选与 SSE 重连无重复、串流；清空单设备后其他设备记录及 body 完整保留，各查看者同步更新。
5. 高流量、慢订阅者和容量淘汰时内存有界，历史、统计及 body 保持一致。
6. 在 2 台与 5 台设备下验证响应、记录及 UI 更新；记录硬件与请求速率，验证后再报告容量。
